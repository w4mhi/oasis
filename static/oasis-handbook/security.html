Security

OASIS is built for a trusted off-grid LAN — keep it there

OASIS is built for a trusted off-grid LAN or hotspot. It binds to 0.0.0.0 so other devices can reach it, and has no authentication — anyone on the same network can use it, including the file browser. That’s the right model for a field net where speed matters more than access control; it is the wrong model for the open internet.

⚠

Don’t expose OASIS to the public internet or an untrusted network. Keep it on your own hotspot/LAN, or behind a firewall/VPN for remote access.

By design

No authenticationAny device on the local network can access OASIS. Intentional for fast field/mesh deployments.
No HTTPSPlain HTTP — appropriate for trusted local networks, not for public or internet-facing use.
Scoped privilegeThe dashboard’s service controls and Wi-Fi helper use narrow, validated sudoers rules — no password ever touches the web layer.
⚠

Winlink’s config.json and the Web SSH terminal both expose credentials/shell over plain HTTP — another reason to keep the whole suite on a trusted network. Never pass Web SSH over an encryption-prohibited RF link.

Troubleshooting

SymptomCause & fix
Is OASIS safe on the open internet?No — and it isn’t meant to be. There is no authentication by design; Web SSH alone is a full shell. Keep it on a trusted LAN or the OASIS AP, never port-forwarded.
I need remote access anywayTunnel it (VPN / SSH) rather than exposing :8083. The threat model is a trusted local network.
