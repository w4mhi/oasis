Wi-Fi AP Fallback

The Pi hosts the OASIS hotspot when no known network is in range

For deployment with no router, the Pi acts as a Wi-Fi access point so other devices can connect directly. OASIS does this automatically — preferring a known network when one is in range, and falling back to its own OASIS hotspot when none is. 

python3 scripts/enable-ap-fallback.py
python3 scripts/enable-ap-fallback.py --ssid FIELD1 --password mypassword
python3 scripts/enable-ap-fallback.py --check     # report status
python3 scripts/enable-ap-fallback.py --disable   # undo

This installs avahi-daemon (so the dashboard resolves at oasis.local), creates a WPA2 hotspot profile, and arms a watcher (oasis-netwatch.service) that raises the AP whenever no known network is reachable. See Accessing OASIS for the connection details.

How it works

oasis-netwatch.serviceAt boot, waits ~25 s for NetworkManager to join a saved network; if none is reachable it raises the hotspot. During operation it polls every 15 s and falls back to the AP after a client link has been gone ~45 s. Logs every decision.
/usr/local/bin/oasis-netctlA pinned privileged helper (scan / connect / forget / ap-up) the dashboard calls via a scoped sudo rule — no password touches the web layer.
⚠

Single radio. The Pi Zero 2 W has one Wi-Fi radio, so it is either a client or the AP, never both. Joining a network from the dashboard drops the AP; any device connected to the hotspot must reconnect at the Pi’s new address.

ℹ

If the OASIS network doesn’t broadcast, the usual causes are a soft-blocked radio or an unset Wi-Fi country (country 00 suppresses 2.4 GHz beaconing). Pass --country US to the enable script, or set it live with sudo iw reg set US.
