RTL-SDR Tuning Bench

Find the gain, PPM, and rate that make an RTL-SDR decode 2 m APRS reliably — a live SSH tool

Getting an RTL-SDR to decode APRS well means finding the right tuner gain, the dongle’s PPM crystal correction, and an audio path that lands in the demodulator’s sweet spot. The tuning bench (features/rtl-sdr/tune-rtl-sdr.py) is a text UI you run over SSH that wraps rtl_fm | sox | direwolf and lets you nudge each knob while watching decode quality live — then it hands you the exact feed command for the live GrayWolf service.

✓

This is a diagnostic bench, separate from the live APRS feed. It uses Direwolf only because its per-2-second audio-stats line is the tuning signal; the production iGate still runs GrayWolf. An RTL-SDR is receive-only — nothing here transmits.

Before you start

Only one process can own the dongle at a time, so stop the live feed first, then launch the bench: 

sudo systemctl stop aprs-sdr-feed.service   # release the USB dongle
python3 features/rtl-sdr/tune-rtl-sdr.py    # 144.390M, 48k by default

It needs rtl_fm, sox, and direwolf (installed by install-rtl-sdr.py). If any are missing it prints the install command and exits instead of crashing. On launch it probes the dongle once — if the device is busy or absent it tells you exactly how to free it before opening the UI.

Launch flagMeaning
--freq 144.800MEU APRS frequency (default is 144.390M, North America)
--rate 24000Bench at 24k audio instead of the 48k default (see the sample-rate note below)
--gain / --ppm / --volStarting values for the live knobs
--conf mine.confReuse an existing Direwolf config instead of the generated one

g/G gain  v/V vol  p/P ppm  r rate  f freq  s sweep  w save  q quit
  • level bar — the receive audio level, updated every 2 seconds from Direwolf’s stats line so it moves even on a silent band. Aim for the green band; red means clipping, dim means too low.
  • audio: flowing — the heartbeat. It proves the RF / USB / audio path is alive independent of decodes, shows the approx sample rate and Direwolf’s error count, and flips to STALLED in red if samples stop arriving. This is the bench’s equivalent of the dashboard’s pkt/s meter.
  • decodes — rolling count over the last 30 s plus the most recent callsigns; the real proof that APRS is being heard.
⚠

Audio flowing ≠ packets decoded. A steady flowing heartbeat means the dongle is producing audio; it does not mean a station was heard. Zero decodes with a healthy heartbeat just means a quiet band — not a broken feed.

Live knobs

Every knob change kills and respawns the pipeline with the new value, so no stray rtl_fm is ever left holding the dongle.

KeyAction
g / GGain down / up through the tuner’s valid steps
v / VSox volume down / up (±0.05)
p / PPPM correction down / up (±1)
rToggle audio sample rate 48k ↔ 24k
fType a new frequency (e.g. 144.800M); validated before it’s applied
sAuto-sweep gain, then PPM
wSave the known-good settings + emit the feed command
qQuit (tears down the pipeline cleanly)

Auto-sweep

Press s to sweep gain across every tuner step, then PPM at the best gain. APRS traffic is bursty, so the sweep is built to be honest about confidence rather than picking noise:

  1. Each step listens up to 60 seconds and counts decodes.
  2. A step must hear at least 3 packets to be scored — more packets is a better score. Fewer than three prints Nothing heard. Inconclusive and is excluded.
  3. The winner is the setting with the most decodes, tie-broken by the cleanest audio level. If no step clears three packets, the sweep reports “inconclusive” and leaves your settings untouched — it never guesses.

A rolling per-step log and an overall time-remaining estimate keep it from being a black box, and the audio heartbeat is shown throughout so an inconclusive step clearly means “quiet band” and not “dead feed.” Press q or Ctrl-C to abort a sweep at any time — it unwinds gracefully back to the live bench without killing the tool.

✓

On a quiet band a full sweep can take a while — that is the price of a trustworthy result. Gain on 2 m has a broad flat plateau; the sweep most earns its keep on PPM, where the dongle’s crystal offset actually matters.

Saving & the GrayWolf handoff

Press w to append a timestamped record to features/rtl-sdr/tune-results.json and print the copy-paste feed command for aprs-sdr-feed.service. That command always uses -s 48000 (GrayWolf’s fixed sample rate) and no sox — only the RF-domain gain and PPM carry over, since those are independent of the bench audio rate: 

rtl_fm -f 144.390M -M fm -s 48000 -g 32.8 -p 0 - | socat -u -b 1920 - UDP-SENDTO:127.0.0.1:7355

See Feeding APRS for wiring that feed into GrayWolf, and remember to restart the feed service when you’re done tuning: sudo systemctl start aprs-sdr-feed.service.

Troubleshooting

SymptomCause & fix
PIPELINE EXITED with usb_claim_interface error -6 The dongle is busy. Stop aprs-sdr-feed.service, kill any stray rtl_fm/rtl_tcp, and if it persists unload the kernel DVB-T driver: sudo modprobe -r dvb_usb_rtl28xxu.
audio: STALLED Pipeline alive but no samples arriving — a USB glitch or the dongle was pulled. Re-seat the dongle; the bench recovers on the next respawn.
Heartbeat rate sags (e.g. ~43k at 48k, shown yellow) The Pi can’t keep up with the audio throughput. On a Pi Zero 2 W, bench at --rate 24000; gain/PPM still carry over to the 48k GrayWolf feed unchanged.
Healthy heartbeat, zero decodes Quiet band, wrong frequency, or antenna. Confirm 144.390M (or 144.800M in the EU) and check the 2 m antenna.
⚠

RTL-SDR needs Raspberry Pi OS Trixie (Debian 13). The Blog V4 needs librtlsdr ≥ 2.0, which only Trixie ships — the same requirement as the live feed.
