Hardware & Deployment

USB / Portable Bundle

Package the whole suite into a self-contained folder that runs anywhere

scripts/create-oasis-offline.py updates all offline packages and packages OASIS into a self-contained oasis-offline/ folder that runs on Windows and Linux with no Python pre-installed. Build it from macOS, Linux, or Windows. 

python3 scripts/create-oasis-offline.py                # incremental build (Linux/macOS/Pi target)
python3 scripts/create-oasis-offline.py --for-windows # also bundle the Windows embedded Python runtime
python3 scripts/create-oasis-offline.py --update      # refresh packages + sync source into oasis-offline/
python3 scripts/create-oasis-offline.py --rebuild     # wipe and clean-rebuild
python3 scripts/create-oasis-offline.py --verify      # verify checksums

What it updates

PhaseWhatDestination
1Python wheels (Flask, gunicorn, psutil — all platforms/versions)server/wheels/
2GrayWolf APRS .deb (arm64, amd64)offline-packages/graywolf/
3Kiwix binariesoffline-packages/kiwix/
4FCC callsign database indexservices/fcc_database/data/
5RTL-SDR .deb packagesoffline-packages/rtl-sdr/
6webssh — ttyd static binariesoffline-packages/webssh/
✓

It’s incremental — run it regularly and it only downloads what changed. Use --rebuild when you need a guaranteed clean slate.

ℹ

From the bundle, the dashboard, ICS forms, FCC lookup, offline maps, calculators, and reference library all work — maps included, since they’re served by the core app. Only the separate Pi services (GrayWolf 8080, Kiwix 8081, APRS history 8085) show as DOWN, since they run as their own services on the Pi.

Troubleshooting

SymptomCause & fix
The build errors outIt needs internet once to vendor wheels/packages, plus free disk. Run it online; re-runs are incremental.
The bundle is hugeLarge data (maps, ZIMs, FCC DB) dominates. Use --update to refresh only what changed, and stage big regions separately.
Target is a Windows machineBuild with --for-windows so the portable launcher and paths are cross-platform.
