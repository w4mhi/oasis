GPS Time Sync & Hardware RTC

Keep an accurate clock with no internet — gpsd + chrony, and a battery-backed RTC

A field station has no internet to pull NTP from, so the clock drifts — and an inaccurate clock breaks FT8/FT4/WSPR/SSTV decode windows and timestamps. A cheap USB GPS receiver fixes this: gpsd reads the GPS, chrony steers the system clock from it, and the header GPS card shows the result.

GPS time sync

python3 features/gps/install-gps.py                 # autodetect the GPS serial device
python3 features/gps/install-gps.py --device /dev/ttyACM0
python3 features/gps/install-gps.py --check         # report gpsd/chrony status

It installs gpsd and chrony, points gpsd at the receiver (GPSD_OPTIONS=-n so it polls without a client), and adds the chrony SHM refclock that disciplines the clock. Run it at home while the Pi has internet — the apt install step needs it once; everything after runs offline.

ℹ

Keep it exercised. GPS almanac data ages out after weeks without a sky view. Power the Pi with the GPS connected and take it outdoors for a few minutes every few weeks — test before deployment, not on arrival. A first outdoor cold fix takes 1–5 minutes.

Hardware RTC (Witty Pi 3)

Without GPS lock or internet, a Pi has no idea what time it is after a reboot — it has no battery-backed clock. A hardware RTC keeps accurate time across reboots and total power loss, the steady baseline GPS/chrony then fine-tune. OASIS supports the UUGear Witty Pi 3 (DS3231 on I²C 0x68): 

python3 features/rtc-hat/enable-rtc.py                  # configure the DS3231 RTC overlay
python3 features/rtc-hat/enable-rtc.py --check          # report status

The script is idempotent and requires a reboot. It enables I²C, adds the i2c-rtc,ds3231 overlay, removes fake-hwclock, and applies the classic DS3231 boot-reset fix. After the reboot, once the clock is correct, write it to the RTC once with sudo hwclock -w.

✓

Any DS3231-based RTC HAT works with the same overlay. Pair GPS + RTC so chrony rides the RTC until GPS reacquires after a power loss.

Troubleshooting

SymptomCause & fix
The clock drifts with no internetThat is what GPS-disciplining fixes. Confirm chrony sees GPS: chronyc sources should list the GPS/PPS refclock; check gpsd is feeding it.
No PPS / coarse time onlyPPS needs the wire connected to the right GPIO. Without PPS you still get seconds-level time from NMEA; with it, sub-millisecond.
Time is right at boot with no fixThe Witty Pi / DS3231 RTC holds time across reboots until GPS locks.
