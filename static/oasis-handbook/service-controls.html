The Dashboard

Service Controls

START / STOP buttons on the dashboard — no SSH required

By default the dashboard shows each companion service’s status but can’t change it — restarting GrayWolf or switching to OpenWebRX would mean SSHing in. The optional service-controls step adds START / STOP buttons to the service cards so you never have to.

ℹ

Not every card has a power button any more. The three hardware-routed radio services — ADS-B, Winlink RF and the APRS SDR feed — are started and stopped by routing a device to them in the SRV OPS hardware console, not from their card. They still need this sudoers rule; they just do not expose the button. OpenWebRX is the explicit exception and keeps its card button, because it picks its own dongle in its own admin UI and never appears in the matrix. See Service Operations.

Enable it from the setup menu, or directly:

python3 scripts/enable-service-controls.py            # grant for the current user
python3 scripts/enable-service-controls.py --user pi  # grant for a specific user
python3 scripts/enable-service-controls.py --check    # report status
python3 scripts/enable-service-controls.py --disable  # remove the permission

How it’s scoped

It installs a narrow, validated sudoers rule (/etc/sudoers.d/oasis-service-controls) built from six named command aliases. Every one is an exact command match — the web endpoints run sudo -n …, so the OS authorises the precise invocation and no password ever touches the web layer. Know what you are granting before you enable it:

AliasWhat it permits
OASIS_SVCsystemctl start|stop|restart|enable|disable for the known OASIS units only (GrayWolf, Winlink, Kiwix, webssh, OpenWebRX, the APRS SDR feed, ADS-B)
OASIS_SNIFFOne fixed read-only tcpdump -ni lo … udp port 7355 — the APRS feed flow meter. Reads a copy of loopback traffic; captures nothing off the network
OASIS_HW_APPLYApplies a device→service assignment from the hardware console
OASIS_HW_EEPROMWrites the EEPROM serial of an RTL-SDR dongle, so two dongles can be told apart
OASIS_APRS_FREQSets the APRS receive frequency
OASIS_REBOOTReboots the Pi
⚠

Two of these reach past starting and stopping services: one writes to dongle hardware and one reboots the machine. Combined with the fact that OASIS has no authentication, anyone who can reach the dashboard can reboot the station. That is the intended trade for a field box on its own hotspot — but it is a reason not to enable service controls on a station parked on a network you do not control. See Security.

ℹ

The OASIS web server’s own unit is deliberately excluded — stopping it would kill the dashboard with no way to bring it back from the browser. The rule is opt-in and fully reversible with --disable.

ℹ

OpenWebRX’s card needs this rule too: starting it there also flips the APRS stack, because the RTL-SDR can only feed one consumer at a time.

Which units

The server keeps its own allowlist — a unit that is not on it is refused with 403 UNKNOWN_SERVICE, whatever the sudoers rule permits. Thirteen units are known:

UnitServiceControllable
graywolfAPRS TNC / iGate / digipeater✓
graywolf-apiThe APRS history / stats API✓
patWinlink (Pat) classic / telnet✓
pat-direwolfWinlink RF — Pat over a direwolf TNC✓
direwolf-drawsThe shared DRAWS TNC. Present so the Winlink card can report status on a DRAWS box; it carries both radio ports, so stopping it takes APRS down with Winlink.✓
aprs-sdr-feedThe RTL-SDR APRS receive chain✓
dump1090-faADS-B receiver — owns the dongle✓
adsb-apiThe ADS-B recorder / history daemon✓
openwebrxOpenWebRX✓
kiwixkiwix-serve✓
websshBrowser terminal✓
gpsdGNSS daemon — status only. It is time infrastructure the whole box leans on, so the web layer may read it but never touch it.—
oasisThe OASIS server itself — status only. Stopping it would kill the dashboard with no way to bring it back from the browser.—

Two units also persist their boot state: starting aprs-sdr-feed or dump1090-fa also enables it, and stopping also disables it, so a station comes back after a power cut in the state you left it. adsb-api follows dump1090-fa through the unit’s own drop-in. A restart never touches boot state. If the enable or disable failed but the action itself succeeded, the response carries a warning rather than pretending it worked.

Device conflicts

Conflict resolution is no longer automatic, and the server never refuses a start on hardware grounds. Device assignment is advisory bookkeeping; a service acquires its dongle or radio port exclusively only when it actually starts. The dashboard resolves contention at click time, with a confirm prompt — and only when there is a real conflict, i.e. another RTL-SDR service is running and it is assigned the same device.

  • OK stops the other service. You then click START again once it is down — deliberately two steps, so nothing is torn down behind your back.
  • Cancel leaves it running and tries anyway, which will fail on the shared dongle. That is still offered, because on a multi-dongle box the bookkeeping can be wrong and the operator is not.
  • Different dongles, or no device assigned at all, means no prompt and the start goes straight through.

Winlink RF is the one coarser case: if GrayWolf is running at all, you are prompted regardless of assignments, because GrayWolf can bind a radio port with no OASIS visibility whatsoever.

ℹ

The SRV OPS hardware console is the other path, and it behaves differently: routing a device there displaces whatever held it, with no prompt. The only thing that can refuse a route is a device lock, which is exactly what locks are for. See Service Operations.

Troubleshooting

SymptomCause & fix
No START / STOP buttons on the cardsEither service controls aren’t enabled — turn them on in setup — or the card is one of the three hardware-routed ones (ADS-B, Winlink RF, APRS SDR feed), which never have a power button. Use the SRV OPS matrix for those.
START does nothing / silently failsThe sudoers scope is missing or the unit errored. Check journalctl -u <service> -e.
A radio service refuses to startThe RTL-SDR is held by another consumer (APRS feed, ADS-B, OpenWebRX, satellite listen). Stop the other one first — the dongle is exclusive. If you were not prompted, the two are assigned different devices on paper but sharing one in practice.
The response mentions SYSTEMD_UNAVAILABLEYou are not on Linux. Service controls are a systemd feature; on a laptop the cards are read-only.
