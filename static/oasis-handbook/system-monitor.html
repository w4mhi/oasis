The Dashboard

System Monitor

Live host health — CPU, RAM, disk, temperature, and Pi power-throttle status

The System Monitor cards in the dashboard header report the health of the host, refreshed every 5 seconds and colour-coded so a problem is obvious at a glance. The data comes from psutil on the server via /api/system; nothing leaves the Pi. The CPU card prints the poll interval (5s) in its corner, so a frozen page is visible without having to guess.

ReadoutWhat it shows
CPUOverall processor load as a percentage, amber from 70%, red from 90%.
Per-core barsOne labelled bar per core (C0, C1…) from the cpu_cores field, each with its own percentage and its own amber/red tint. A single pegged core looks completely different from a genuinely loaded box, and this is where you see the difference.
TempSoC temperature — watch this in an enclosure or full sun. Shown in your chosen units, but the amber/red thresholds are fixed at 65 °C and 80 °C.
Fan glyphFrom the cooling field. It appears only when a cooling service is installed (Argon fan or RGB cooling HAT); it spins when the fan service is running and the SoC is above roughly 55 °C, sits still when idle, and tints with temperature. No fan installed means no glyph — not a broken fan.
RAMPercent used only — not “used / total”. Amber from 70%, red from 90%.
DISKPercent used — not free space. Amber from 80%, red from 92%.
Card borderThe CPU card’s border and dot track the worst of CPU, temperature and RAM — any one of the three can drive it. Disk is deliberately excluded: a 95%-full card is a housekeeping job, not a live fault.
PROCESSES cardThe top_procs field — the top three processes by CPU, each with its CPU and RAM share, plus the 1-minute load average. This is what turns “the box is hot” into “this is what is doing it”.
POWER pillPi power-throttle / under-voltage status.
HOST pillHostname and the address to reach the dashboard on (e.g. 10.42.0.1 in AP mode).
UPTIME pillTime since last boot. It rides on the OPS section header, not in the card row.
Wi-Fi pillThe SSID when connected, OASIS when hosting the access point, dim when not connected, and hidden entirely on a box with no Wi-Fi support. Signal strength drives the colour only — it is never printed, and there is no connected-client count.
ℹ

Under-voltage (a lightning-bolt throttle flag) is the most common field gremlin — it points at the power supply or cable, not the Pi. A GPS or SDR dongle browning out the 5 V rail shows up here first.

ℹ

There is no audio readout on the dashboard. Audio device detection is a setup-time and diagnostic concern — see Audio Hardware.

✓

The same checks are available headless over SSH with doctor.py — handy when no browser is at hand.

Troubleshooting

SymptomCause & fix
TEMP is red / the Pi throttlesThermal throttling. Improve cooling (the RGB Cooling HAT helps) and check vcgencmd get_throttled (non-zero = throttled now or since boot).
A value shows n/aTelemetry stalled. Hard-refresh; confirm /api/system answers on :8083. A 503 with code SYSTEM_METRICS_UNAVAILABLE means psutil is not installed — reinstall the server feature from the setup menu.
No fan glyph on the CPU cardNo cooling service is installed. Expected on a bare Pi — add argon-fan or rgb-cooling-hat from the setup menu if you have the hardware.
HDOP is redPoor GPS geometry, not a fault — see the GPS card. It clears as more satellites lock.
DISK near fullLarge data (maps, ZIMs, recordings) fills the card. Move them to external storage or prune; OASIS itself is tiny.
