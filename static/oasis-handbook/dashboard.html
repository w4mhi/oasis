The Dashboard

Dashboard Tour

The single page every operator opens — status, services, and every tool

The dashboard at http://<host-ip>:8083 is the home screen for the whole suite. It is one page, refreshed live, that shows the health of the station and links to every tool. It works on a phone as well as a desktop.

Header

The header is a row of cards, not the old SYSTEM stat bar. Left to right:

CardShows
LOCAL and UTC clocksTwo clock cards, ticking every second. The UTC card also carries the running OASIS version.
GPSFix badge (3D FIX / 2D FIX / NO FIX / NO GPS), an interface badge (USB or UART), then Sats, HDOP, Alt, Lat, Lon and Clock. See the GPS / GNSS card.
CPUCPU and Temp in the header, RAM and DISK below, a per-core bar for every core (C0, C1…), and a fan glyph that appears only when a cooling service is installed — spinning when it is actually turning. The card border tracks the worst of CPU, temperature and RAM.
PROCESSESThe top three processes by CPU, with CPU and RAM columns, plus the 1-minute load average.
SRV OPS railA vertical burger button pinned to the far right — the entry to the hardware console. See below.

Host, LAN IP, power/throttle state and the callsign/grid are pills, not cards, tucked under the OASIS brand block alongside the units toggle, the theme toggle and the Wi-Fi pill (the SSID when connected, OASIS when hosting the access point, and hidden entirely on a box with no Wi-Fi support). Uptime is a pill too, but it rides on the OPS section header further down the page, not in the header.

These cards are fed by /api/system and refresh every 5 seconds — the CPU card prints that interval (5s) so you can see at a glance that it is live. Full detail in System Monitor.

SRV OPS — the hardware console

The SRV OPS rail at the top right opens the HW / SRV Matrix: a device×service grid where you route an RTL-SDR or a radio port to a service, lock a device so nothing can take it, or Stop all. The rail itself is a health indicator — green with a tick when everything is nominal, amber or red with a count when it is not. This is the control surface for every hardware-bound radio service; see Service Operations.

Service strips

Below the header sit two strips of service cards. The section header counts them and carries a SHOW n NOT INSTALLED toggle.

StripCards
Radio / RFWeb SSH, APRS GrayWolf, APRS SDR Feed, ADS-B Aircraft, Winlink RF, Wiki Kiwix.
System / infrastructureFrontend Flask, Web Server (badged gunicorn or werkzeug), GPS (gpsd), APRS Stats API. Single-row cards — colour only, no buttons.

The old Winlink Classic Mail card is gone: classic telnet / the Pat web UI is now reached from the Use classic Winlink button on the Winlink page. In its place is a Winlink RF card, which additionally shows an unread-mail count.

⚠

Not every card has START / STOP. The three hardware-routed cards — ADS-B Aircraft, Winlink RF and the APRS SDR Feed — deliberately have no per-card power button, because they are started by routing a device to them in the SRV OPS matrix. ADS-B and Winlink RF get an OPEN ↗ button instead; the APRS SDR feed gets neither and is purely matrix-driven. OpenWebRX has no card at all since 3.92.0 — it picks its own dongle in its own admin UI, so OASIS stopped pretending to manage it; start it over SSH. Everything else with a systemd unit still has START / STOP, provided you enabled service controls. See Service Operations.

Cards for services that hold a dongle or a radio port also show a read-only device: row naming what they were routed to.

TRAFFIC LIVE

The live table is TRAFFIC LIVE — it merges APRS and ADS-B into one list, and reads TRAFFIC OFFLINE when the APRS Stats API is not answering. Ten columns: Callsign, Type, Last Heard, Age, Speed, Altitude, Grid, Dist, Via, Comment. Clicking a callsign opens the live map focused on that station; see Stations & History.

Five columns carry their own per-column filter behind a small ▼ toggle: Callsign (prefix or * wildcard), Type, Age (defaults to ≤ 24 h), Grid, and Via. Above the table sit three sets of chips:

ChipsWhat they do
Source pills — RF, IS, ADS-BOne per receive path: APRS heard off the air, APRS via APRS-IS, and aircraft via ADS-B. Additive, always rendered even at zero, remembered per browser.
Hazard pillsConfig-driven from configuration/hazards.json — fire, hurricane, tornado, flood, smoke, skywarn and emergency ship by default, matched on APRS symbol. A pill appears only for a hazard actually being heard, and tapping it filters to that hazard alone. A wildfire reported 100% contained drops out.
Emergency chipSeparate from the hazard pills: public-safety stations heard in the last 48 hours. Reads ✓ No emergency POI when calm and ⚠ N EMERGENCY POI when not. Tapping it filters to those, and it is mutually exclusive with the hazard pills.

Troubleshooting

SymptomCause & fix
A service card is grey / NOT INSTALLEDThat companion isn’t installed. Add it from the setup menu; click SHOW N NOT INSTALLED to reveal hidden cards.
A card is red / DOWNThe service crashed or was stopped. Use START (if service controls are on) or sudo systemctl restart <service>.
A card has no START button at allExpected for ADS-B, Winlink RF and the APRS SDR feed — route a device to them from the SRV OPS matrix instead. See Service Operations.
Stats or the clock look frozenThe system cards refresh every 5 s and the clocks every second. If nothing is moving the browser lost the poll — hard-refresh.
Everything greys out at onceThe Flask app went down. sudo systemctl restart oasis.
